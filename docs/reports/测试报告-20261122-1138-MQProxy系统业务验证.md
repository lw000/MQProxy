# 测试报告：MQProxy 系统业务验证

## 1. 测试范围

- 验证对象：`build-verify/bin/Debug/MQProxy.exe`（本轮整改后构建产物）。
- 场景：SYS1 启动与订阅链路、SYS2 消息消费一致性、SYS3 showContent 内容开关、SYS4 优雅退出（两个进程实例各验证一次）、SYS5 配置异常快速失败。
- 涉及文件：`config.toml`（新增，gitignore）、`tests/kafka/run_system_validation.py`（新增）、`tests/kafka/reports/sysval-20261122-1137.md`。
- 不在范围：长时间稳定性/压力测试、KRaft 模式、SASL/SSL 认证场景。

## 2. 测试方法

环境：Windows 10 / Kafka 3.3.1（`C:/tools/kafka_2.12-3.3.1`，ZK 模式）/ Java 8 / Python 3.7。命令：

```
cd c:/github/cpp_works/MQProxy/tests/kafka
python -m py_compile run_system_validation.py
python run_system_validation.py
```

脚本自动执行：启动 Kafka → 确保 topic 存在 → 启动 MQProxy → 生产 10 条唯一 token 消息 → 轮询日志 → CTRL_BREAK 优雅退出 → 切换 showContent=false 重启验证 → 异常配置验证 → 停止 Kafka。

## 3. 测试结果

| 场景 | 判定条件 | 结果 | 证据 |
| --- | --- | --- | --- |
| SYS1 | 进程存活且日志含 initialized/Subscribed/running/Assigned | PASS | 四项均 True |
| SYS2 | 生产 10 条，日志命中 10 条且内容逐条一致 | PASS | 命中=10，一致=True，flush 后 10/10 |
| SYS4（实例1） | CTRL_BREAK 后 exit=0、收尾日志存在、无残留进程 | PASS | exit=0，三项满足 |
| SYS3 | showContent=false 时仅记录长度、不泄漏 payload 明文 | PASS | 含长度=True，泄漏=False |
| SYS4（实例2） | 同实例1 | PASS | exit=0 |
| SYS5 | 不存在的配置文件 → exit=1 且错误信息正确 | PASS | exit=1，错误信息=True |
| 汇总 | 全部 PASS，退出码 0 | **6/6 PASS** | `tests/kafka/reports/sysval-20261122-1137.md` |

进程清理：`tasklist` 确认无残留 java.exe 与 MQProxy.exe。

## 4. 已知问题

- PowerShell 控制台下服务管理日志中文显示乱码（文件为 UTF-8，功能不受影响）。
- `flush_on(info)` 导致 debug 级 payload 日志在进程退出前可能未落盘；验证脚本已在优雅退出后复核，生产环境如需实时可见可调低 flush 级别。
- KRaft / SASL / SSL 场景未验证。

# 测试报告：动态配置存储与 Web 管理

## 1. 测试范围

本次交付将 MQProxy 由扁平结构重构为 `apps/services/common` 分层，并新增 SQLite 动态配置、Web 管理页、Kafka 动态启停重启与日志参数动态调整。

覆盖模块与文件：

- 入口与构建：`apps/mqproxy/main.cc`、`CMakeLists.txt`、`config.example.toml`、`README.md`、`.gitignore`
- 公共层：`common/include/common/*`（`service_base.hxx`、`service_manager.hxx`、`bootstrap_config.hxx`、`logger.hxx`）、`common/src/*`、`common/CMakeLists.txt`
- 配置存储：`services/config_store/**`（SQLiteCpp，`logger_config` / `kafka_config` 两张表）
- Kafka 管理：`services/kafka_manager/**`（配置重载、start/stop/restart、消费线程）
- Web 服务：`services/web_server/**`、`web/index.html`（静态页 + REST API）
- 验证脚本：`tests/kafka/run_dynamic_validation.py`

不在本次范围：长时间压力/稳定性测试、SASL/SSL 认证链路、Web API 鉴权、多客户端并发压测、KRaft 模式。

## 2. 测试方法

环境：Windows 10 / Visual Studio 2019 / CMake 3.15+ / vcpkg `C:/vcpkg` / Python 3.7 / Kafka 3.3.1（ZK 模式，`C:/tools/kafka_2.12-3.3.1`）。

命令（可复制重放）：

```bash
cd c:/github/cpp_works/MQProxy
cmake -S . -B build-verify -G "Visual Studio 16 2019" -A x64
cmake --build build-verify --config Debug

cd tests/kafka
python -m py_compile run_dynamic_validation.py
python run_dynamic_validation.py
python run_system_validation.py
```

脚本自动完成：启动 Kafka 并创建 topic → 生成独立 TOML/SQLite/日志路径 → 启动 MQProxy → 依次执行 12 项动态配置与 Web 用例 → 优雅停进程 → 重启进程验证持久化 → 停止 Kafka。既有 `run_system_validation.py` 用于回归原消费链路。

## 4. 已知问题

- 日志等级调为 error(4) 及以上时，INFO 级收尾日志按设计被过滤；验证脚本 EXIT1 以退出码判定优雅退出。
- Web REST API 未实现鉴权，仅适合内网/本地管理场景；暴露到公网前需增加访问控制。
- cpp-httplib 0.66.0 要求 Windows 10 及以上（构建已定义 `_WIN32_WINNT=0x0A00`）；更低版本系统无法编译 Web 服务。
- 管理页静态目录由 `[SERVER].webroot` 注入，相对路径按进程工作目录解析；脱离源码目录运行时应配置为绝对路径。

# 测试报告：Playwright M1 用例生成

## 1. 测试范围

在 M0 骨架基础上，使用 Playwright-MCP 实地探索管理页，由 AI 依据可访问性树生成 5 条非 smoke 用例，并把公共桩数据抽取为共享 helper。

涉及文件：

- `tests/e2e/helpers.js`（新增）：统一配置常量、API 打桩与调用计数，支持 override。
- `tests/e2e/management.spec.js`（新增）：5 条用例——Kafka 保存 payload、停止/启动、日志保存与重启、非法配置错误处理、刷新重新拉取状态。
- `tests/e2e/smoke.spec.js`（修改）：改为复用 `helpers.js`，原 3 条断言不变。
- `README.md`（修改）：E2E 用例数更新为 8。

不在范围：真实后端联调、AI 自愈 PR 流程（M3）、CI 流水线（M2）。

## 2. 测试方法

环境同 M0：Windows 10 / Node.js v26.13.1 / Playwright CLI 1.65.1 / Chromium 159.0.8154.6。

探索步骤（Playwright-MCP）：

1. 启动本地静态服务 `python -m http.server 8765 --bind 127.0.0.1`。
2. MCP `browser_navigate` → `http://127.0.0.1:8765/web/index.html`。
3. MCP `browser_snapshot` 获取 AXTree：发现页面有两个同名"保存配置"按钮和两个"重启生效"按钮，语义定位会歧义。
4. MCP `browser_evaluate` 枚举 18 个 `data-testid`，确认 M0 锚点全部存在，据此生成基于 `getByTestId` 的用例。

执行命令：

```powershell
cd c:/github/cpp_works/MQProxy
$env:Path = 'C:\Program Files\nodejs;C:\Users\lwstar\AppData\Roaming\npm;' + $env:Path
$env:NODE_PATH = 'C:\Users\lwstar\AppData\Roaming\npm\node_modules;C:\Users\lwstar\AppData\Roaming\npm\node_modules\@playwright\test\node_modules'
playwright test --config tests/e2e/playwright.config.js
```

## 4. 已知问题

- 用例仍以 `page.route` 打桩，验证的是页面交互契约而非真实后端行为；真实链路由 `run_dynamic_validation.py` 覆盖。
- MCP AXTree 中状态面板初始为"加载中..."，因静态服务下 `/api/*` 返回 404；属预期，用例通过打桩提供数据。
- 全局安装导致 `NODE_PATH` 必须显式设置；M2 接 CI 时需改为项目级依赖清单以保证可复现。
- `.playwright-mcp/` 下的探索快照已加入 `.gitignore`，不入库。

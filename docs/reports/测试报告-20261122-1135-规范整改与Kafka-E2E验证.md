# 测试报告：代码规范整改与 Kafka 单机 E2E 验证

## 1. 测试范围

- 代码规范整改涉及文件：`CMakeLists.txt`、`include/Config.hxx`、`include/KafkaConsumer.hxx`、`include/Logger.hxx`、`src/Config.cc`、`src/KafkaConsumer.cc`、`src/Logger.cc`、`src/main.cc`。
- 测试工具新增：`tests/kafka/kafka-local.toml`、`kafka_common.py`、`kafka_service.py`、`run_e2e.py`、`.gitignore`。
- 不在本次范围：MQProxy 可执行程序对真实 Kafka 的长时间稳定性/压力测试、KRaft 模式验证、SASL/SSL 认证场景。

## 2. 测试方法

环境：Windows 10 / VS 2019 BuildTools / CMake 4.5 / vcpkg `C:/vcpkg`（cppkafka、spdlog 1.17、nlohmann_json 3.12）/ Python 3.7（tomli 2.0.1）/ Kafka 3.3.1（`C:/tools/kafka_2.12-3.3.1`）/ Java 8。

构建：
```
cd c:/github/cpp_works/MQProxy
cmake -S . -B build-verify -G "Visual Studio 16 2019" -A x64 -DCMAKE_BUILD_TYPE=Debug
cmake --build build-verify --config Debug
```
格式抽查：
```
Select-String -Path "include/*.hxx","src/*.cc","tests/kafka/*.py" -Pattern "`t" | Measure-Object
```
服务管理与 E2E：
```
cd tests/kafka
python kafka_service.py start
python kafka_service.py status
python kafka_service.py stop
python run_e2e.py
```

## 4. 已知问题

- 服务管理日志中的中文在部分 PowerShell 控制台显示为乱码（文件本身为 UTF-8，不影响功能）。
- 每次干净启动会在配置的数据根目录下创建独立 `run-<时间戳>` 子目录，长期运行会积累目录，需人工清理。
- KRaft 模式与 SASL/SSL 场景未在本轮验证范围内。

# 测试报告：config_store 数据库访问命名参数整改（方案 A）

## 1. 测试范围

按人工确认的方案 A，将 `services/config_store/src/config_store.cc` 中全部按数字索引的数据库访问整改为按列名/命名参数访问，落实 `AGENTS.md`「数据库访问规范」与 `CODEBUDDY.md` C11 条款。

覆盖改动：

- `services/config_store/src/config_store.cc`：`seedIfEmpty`、`getLoggerConfig`、`setLoggerConfig`、`getKafkaConfig`、`setKafkaConfig` 五个函数；两处 `SELECT COUNT(*)` 增加 `row_count` 别名；两处 INSERT、两处 UPDATE 改为 `:列名` 命名占位符与 `bind(":列名", 值)`；所有 `getColumn(数字)` 改为 `getColumn("列名")`。
- `AGENTS.md`、`CODEBUDDY.md`：13:36 已同步的规则文档（本次整改的验收依据）。
- `changelog/2026-11-22.md`、`CHANGELOG.md`：变更记录与索引。
- 本报告文件。

不在本次范围：其他服务源码（`kafka_manager`、`web_server`、`common`）、构建配置、Kafka 服务端实现、Web API 鉴权、长时间压力测试。

## 2. 测试方法

环境：Windows 10 / Visual Studio 2019 / CMake 3.15+ / vcpkg `C:/vcpkg` / Python 3 / Kafka 3.3.1（ZK 模式）。

命令（可复制重放）：

```powershell
cd c:/github/cpp_works/MQProxy
cmake --build build-verify --config Debug

Select-String -Path services/config_store/src/config_store.cc `
  -Pattern '\.bind\(\d|getColumn\(\d|SELECT \*'

cd tests/kafka
python run_dynamic_validation.py
python run_system_validation.py
```

`run_dynamic_validation.py` 自动启动 Zookeeper + Kafka broker，生成独立 TOML/SQLite/日志路径，覆盖配置读写与持久化、Web API、Kafka 启停重启、日志参数动态调整共 12 项；`run_system_validation.py` 覆盖启动订阅、消费一致性、优雅退出、showContent 开关、异常快速失败共 6 项；两脚本收尾均停止 Kafka 与 MQProxy。

## 4. 已知问题

- IDE 的 C/C++ 扩展对 `config_store.cc` 报 5 条 `cannot open source file`（`spdlog/spdlog.h`、`SQLiteCpp/Database.h`、`SQLiteCpp/Statement.h`、`sqlite3.h` 及包含链错误），原因为该扩展的 `configurationProvider` 未配置 vcpkg include 路径；属改动前既有的编辑器配置问题，不影响 MSVC 构建（实测 0 error / 0 warning）。
- 本次整改只覆盖 `config_store.cc`；若后续新增其他数据库访问代码，仍须按 C11 / AGENTS.md 规则使用列名与命名参数。

# 测试报告：Playwright M3 失败归因与定位器自愈

## 1. 测试范围

在 M2 的 CI 结果分析基础上，增加失败分类归因与定位器漂移自愈建议，并用变异实验验证"注入漂移 → 检出 → 建议 → 恢复"闭环。所有自愈产物仅供人工审核，不自动修改源码、不自动合并 PR。

涉及文件：

- `tests/e2e/analyze_results.py`（修改）：新增 `product_bug` / `test_locator_drift` / `environment` / `flaky_or_slow` / `test_assertion` 分类，提取失败中的 `getByTestId` 列表，合并 JUnit `message` 属性与正文。
- `tests/e2e/heal_locators.py`（新增）：基于当前 `web/index.html` 的 `data-testid` 集合，用相似度匹配给出替换建议，产出 `healing-proposal.json`、`healing-proposal.patch`、`healing-pr-body.md`；不写回源码。
- `.github/workflows/e2e.yml`（修改）：E2E job 失败时运行 `heal_locators.py`，产物随 `test-results/` 上传。
- `tests/e2e/run_healing_validation.py`（新增）：变异验证脚本，临时把 `kafka-save` 改为 `kafka-save-v2`，验证归因与建议后恢复页面并跑全量。
- `README.md`（修改）：同步 M3 命令与"不自动合并"说明。

不在范围：GitHub PR 自动创建与合并、基于 LLM 的语义级修复、真实后端故障注入。

## 2. 测试方法

环境同 M2（Windows 10 / Node.js v26.13.1 / Playwright 1.65.1 / Python 3.7）。

命令：

```powershell
cd c:/github/cpp_works/MQProxy
python tests/e2e/run_healing_validation.py
```

脚本内依次执行：`npm test -- -g "Kafka 配置保存发送正确 payload"`（预期失败）→ `python analyze_results.py` → `python heal_locators.py` → 恢复 `web/index.html` → `npm test`（预期全绿）。备份存于系统临时目录，避免被 Playwright 清理 `test-results/` 时误删。

## 4. 已知问题

- 自愈采用字符串相似度，而非 LLM 语义判断；复杂改名（如改为语义完全不同的 `data-testid`）可能无建议或误判，需人工审核。
- 变异验证最后的全量测试会清空 `test-results/`，因此本次运行中生成的 patch 与 PR 描述被覆盖；CI 场景下产物在失败 job 中上传，不受影响。
- 尚未实现 GitHub PR 自动创建；当前只产出 PR 描述与 patch 文件，由人工决定如何应用。
- 分类规则为关键词启发式，可能把"超时但含 locator 字样"的失败优先归为定位器漂移；置信度阈值仅用于建议生成，未做概率校准。

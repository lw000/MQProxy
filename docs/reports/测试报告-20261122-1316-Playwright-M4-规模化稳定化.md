# 测试报告：Playwright M4 规模化与稳定化

## 1. 测试范围

在 M3 闭环基础上扩展 E2E 覆盖至 12 条业务场景，加入分片运行、flaky 隔离与指标看板，并将 CI 改为 3 分片矩阵。

涉及文件：

- `tests/e2e/business.spec.js`（新增）：4 条场景——Kafka 保存后不生效、重启后生效、日志保存与重启生效、非法日志配置处理。
- `tests/e2e/quarantine.json`（新增）：flaky 用例登记清单，初始为空。
- `tests/e2e/playwright.config.js`（修改）：按 `quarantine.json` 设置 `grepInvert`，从主套件排除隔离用例。
- `tests/e2e/playwright.quarantine.config.js`（新增）：仅运行隔离用例的独立配置。
- `tests/e2e/package.json`（修改）：新增 `test:quarantine` 脚本。
- `tests/e2e/generate_dashboard.py`（新增）：累积历史指标并生成 `test-results/dashboard.html`。
- `tests/e2e/run_m4_validation.py`（新增）：全量/分片/隔离/看板一体化验证。
- `.github/workflows/e2e.yml`（修改）：e2e job 改为 `shard: [1,2,3]` 矩阵，制品按分片命名。
- `.gitignore`（修改）：忽略 `tests/e2e/metrics/`。
- `README.md`（修改）：同步 12 条用例、隔离与看板命令、分片说明。

不在范围：CI 远端执行、跨分片看板聚合、flaky 自动登记（当前需人工写入 `quarantine.json`）。

## 2. 测试方法

环境同 M3。命令：

```powershell
cd c:/github/cpp_works/MQProxy
python tests/e2e/run_m4_validation.py
```

脚本依次执行：全量 12 条 → 分析 → 生成看板 → 2 分片运行 → 注入一条 flaky 登记后主套件运行与隔离套件运行 → 恢复登记 → 再次全量。备份存系统临时目录，finally 恢复。

## 4. 已知问题

- `fullyParallel: false` 下 Playwright 按文件组分片，两片为 9+3 而非均分 6+6；CI 三片也可能不均等，但总覆盖完整。
- 看板历史写入本地 `tests/e2e/metrics/history.jsonl`，CI 各分片尚未聚合成统一看板。
- flaky 隔离需人工把用例名写入 `quarantine.json`，尚未从 `analysis.json` 自动提名。
- 全局 Node 与本机 Python 3.7 的环境差异仍在；CI 使用 Node 20，首次远端运行需观察。
- 12 条 E2E 以 API 打桩验证 UI 契约，真实后端持久与消费链路仍由 `run_dynamic_validation.py`（12/12）覆盖。

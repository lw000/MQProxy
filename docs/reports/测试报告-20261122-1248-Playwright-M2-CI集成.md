# 测试报告：Playwright M2 CI 集成

## 1. 测试范围

将 M1 的 E2E 用例接入 GitHub Actions，并以项目级依赖清单替代全局安装带来的 `NODE_PATH` 依赖；新增 JUnit 结果分析产物。

涉及文件：

- `.github/workflows/e2e.yml`（新增）：build / e2e / system-validation 三个 job，PR、push、每日定时与手动触发。
- `tests/e2e/package.json`、`tests/e2e/package-lock.json`（新增）：锁定 `@playwright/test@1.65.1`、`@playwright/mcp@0.0.86`，提供 `npm test`。
- `tests/e2e/playwright.config.js`（修改）：新增 JUnit reporter，输出 `test-results/junit.xml`。
- `tests/e2e/analyze_results.py`（新增）：解析 JUnit，分类失败并输出 `test-results/analysis.json`。
- `.gitignore`（修改）：忽略 `node_modules/`。
- `README.md`（修改）：改为 `npm install --prefix` / `npm test --prefix` 的可复制命令，补充 CI 说明。

不在范围：GitHub Actions 在远端 runner 上的真实执行、AI 失败归因机器人与自愈 PR（M3）、Playwright 鉴权测试。

## 2. 测试方法

环境：Windows 10 / Node.js v26.13.1 / npm 11.20.0 / Python 3.7。

命令（可复制重放）：

```powershell
cd c:/github/cpp_works/MQProxy
$env:Path = 'C:\Program Files\nodejs;C:\Users\lwstar\AppData\Roaming\npm;' + $env:Path
npm install --prefix tests/e2e
npm test --prefix tests/e2e
python tests/e2e/analyze_results.py
```

CI 各 job 的核心命令均在本地等价重放：`cmake` 构建（前序报告已验证）、`npm ci`→`npx playwright install chromium`→`npm test`、`python run_dynamic_validation.py` / `run_system_validation.py`（前序报告 12/12、6/6）。

## 4. 已知问题

- GitHub Actions workflow 未在远端实际执行（无 GitHub 推送动作）；本地只等价重放了各 job 的核心命令，YAML 语法也未经解析器机器校验（本机无 PyYAML）。首次推送后需观察 Actions 运行结果。
- workflow 使用 `self-hosted, windows, x64` runner，要求 runner 具备 VS 2019、`C:/tools` 下的 Kafka 与 Python 3.7；不满足时 system-validation job 会失败。
- CI 用 `setup-node` 固定 Node 20，本地为 Node 26；Playwright 版本已由 lock 文件锁定，但 Node 差异仍可能带来边缘行为。
- 失败分析目前输出 `analysis.json` 制品，尚未接入 PR 评论机器人与自愈 PR（M3）。
- 每日定时任务 `cron: '0 16 * * *'` 为 UTC 16:00（北京时间次日 00:00）。
